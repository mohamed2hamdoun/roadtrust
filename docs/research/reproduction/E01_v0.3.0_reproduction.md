**Status: complete · 9 October 2026 · Plan step 0.2**

## Result

**Reproduced exactly.** A clean checkout of tag `v0.3.0-hackathon` (`b4c4a03`), with a
fresh environment installed from `uv.lock`, regenerated the same dataset byte for byte and
trained a model whose every detection metric equals the archived `evaluation.json`. The

This run is the reference row the rebuilt system's benchmark (plan P6) must beat.

## Findings recorded for the rebuild

1. **The score is not a vote fraction** (audit A01, measured on the archived model before
   this run). With `min_samples_leaf=2` and `balanced_subsample` weights, `predict_proba`
   differs from the true fraction of tree votes by up to 0.0696; 8.4 % of test messages
   differ by more than 0.01, and 56 of 32,297 test decisions flip at threshold 0.35.
   Training and inference both use `predict_proba`, so the metrics are consistent; the
   descriptions in the old docs and UI are wrong. Rebuild rule: name the exact model
   output wherever a score is shown.
2. **Python version is not pinned.** `uv.lock` pins packages but allows Python 3.11–3.13;
   a fresh install picked 3.13.5 while the archive used 3.12.10. Results did not change
   here, but the rebuild should pin Python (decide in plan step 0.4).
3. **No data hash in model metadata.** `model_meta.json` stores the data path, not its
   checksum, so a model cannot be tied to the exact data it learned from. Rebuild rule:
   every model bundle records the SHA-256 of its training manifest.
4. **Stale metadata on disk.** The local `ids_model.pkl` is version
   `ids-rf-2.0.0-20261007T163449Z`; the committed `model_meta.json` says
   `…20261003T052650Z`. Scores are identical, so it is harmless here, but the rebuild
   must keep a model and its metadata in one versioned bundle.

## What this does not show

Reproducibility of a synthetic benchmark on one machine. It says nothing about detection on
real traffic, other datasets or other hardware. Those are the questions for P4–P6.
